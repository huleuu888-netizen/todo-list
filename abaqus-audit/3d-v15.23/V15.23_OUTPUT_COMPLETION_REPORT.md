# V15.23 S01 Output Completion Report

FINAL_STATUS = S01_OUTPUT_REQUEST_COMPLETED_RERUN_REQUIRED

## Scope

This version audits the V15.21 S01 input and ODB and generates an output-only
replacement input. It does not change geometry, mesh, materials, permeability,
loads, boundary conditions, or any S02-S07 case.

## Findings

- Existing `POR` output is valid pore pressure. It is present at nodal and
  integration-point locations and was read correctly in V15.22.
- Existing `FLVEL` output is valid element integration-point pore-fluid
  effective velocity. It is not total discharge Q.
- Existing S01 output requests do not include `RVF`, `FLDVEL`, or `COORD`.
- No direct `HEAD` or hydraulic-gradient field is available in this output
  definition. `HFL` is not inserted because it is a heat-flux variable, not a
  pore-pressure hydraulic-gradient variable.
- The existing history output is preselected assembly energy/time output; it
  does not provide a boundary flow-rate history.

## Output-only correction

`modify_S01_output_request.py` creates:

`v15_23_S01_OUTPUT_COMPLETION.inp`

The generated node output request is:

```text
POR, RF, U, COORD, RVF, FLDVEL
```

The element output request remains:

```text
FLVEL, POR, S, EVOL
```

`RVF` is selected because the existing S01 deck prescribes pore pressure at
DOF 8 on the upstream/downstream boundary node sets. The next postprocessor
can sum `RVF` over the confirmed downstream boundary sets to obtain a signed
boundary flow rate, subject to the model's unit convention. `COORD` plus `POR`
supports documented head and gradient calculations; it does not silently
freeze a conversion factor.

## Must S01 be rerun?

Yes. The existing ODB cannot be repaired by direct post-processing because
`RVF`, `FLDVEL`, and `COORD` were not written as requested output, and Abaqus
does not retroactively add missing variables to an existing ODB. S01 must be
rerun using the generated output-completion input. This is an output-definition
rerun only; it does not authorize changes to the physical model.

S02-S07 were not run.

## POR anomaly disposition

The POR range is not evidence that the extractor read the wrong variable. The
field key is `POR`, and the ODB exposes it at both `NODAL` and
`INTEGRATION_POINT` locations. The values are pressure, not head. Their scale
must be checked against the prescribed DOF-8 boundary values, the initial
pore-pressure data, the coordinate elevations, and the declared self-
consistent unit system. V15.23 does not change POR values or material data to
make the range appear plausible.

## Required variables for the next S01 run

Save these field outputs at the final increment:

### Nodes

- `POR`: pore pressure;
- `RVF`: reaction fluid volume flux at prescribed-pressure nodes;
- `FLDVEL`: nodal fluid velocity;
- `COORD`: node coordinates;
- retain `RF` and `U` for the existing mechanical audit.

### Elements

- `FLVEL`: element integration-point effective fluid velocity;
- retain `POR`, `EVOL`, and `S` from the existing request.

For Q, the next analysis should also retain the mapping of the actual
downstream `S00_D_*` node sets so `RVF` can be summed over the correct boundary
without including internal or upstream nodes. For head and gradient, the
postprocessor must document the pressure-to-head convention and elevation
mapping before reporting a number.
